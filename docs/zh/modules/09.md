## 09.1 任务分解与组织结构

`core` · 设计：在约束下选择架构并论证取舍

先修：[07.3 Harness 职责与 Agent—环境接口](../modules/07.md#unit-07-3), [11.2 分层指标与 Agent 轨迹评测](../modules/11.md#unit-11-2)

### 知识框架

- 单 Agent、固定并行、multi-agent 的选择
- supervisor、hierarchical、peer/swarm 和 blackboard
- 角色专长、工具范围、上下文和责任分配
- 独立子任务、依赖链、共享约束与终止
- 协调开销、错误传播和收益假设

### 资源与阅读范围

[Stanford CS329Z: Engineering AI Agents](https://cs329z.stanford.edu/) — Agent 工程主干课程：按已发布材料串联框架、数据、优化、评测与安全。

Multi-Agent 主题；配合论文和框架示例。

### 动手任务

对研究/分析任务提出可验证的协作增益假设。

### 自测题

1. 什么情况下多 Agent 优于单 Agent？多 Agent 会带来哪些额外成本（协调、token、错误传播）？
2. 一个多 Agent 系统比单 Agent 基线更慢、更贵，质量也没有提升，你如何分析原因？
3. 为“撰写一份行业调研报告”设计组织结构（supervisor、层级或对等），说明各 Agent 的职责、工具范围和终止条件。

<a id="unit-09-2"></a>

## 09.2 通信、交接与任务账本

`advanced` · 实现：独立完成小型实现并验证行为

先修：[09.1 任务分解与组织结构](../modules/09.md#unit-09-1), [01.3 异步、并发与取消](../modules/01.md#unit-01-3)

### 知识框架

- 消息 schema、任务/结果契约与路由
- handoff、subagent-as-tool 和共享消息板
- 任务 ID、负责人、lease、状态和 artifact ledger
- 消息丢失、重复、乱序、超时与死锁
- 通信 token、信息压缩与上下文污染

### 资源与阅读范围

[Google Agent Development Kit](https://google.github.io/adk-docs/) — 第二框架选项：sessions、tools、workflow agents、部署与评测。

Multi-agent、handoff、session 与通信示例。

### 动手任务

实现两个 worker 交付 artifact 的协调流程。

### 自测题

1. 比较“handoff 移交控制权”和“子 Agent 作为工具调用”两种模式在上下文传递和责任边界上的差异。
2. 两个 Agent 互相等待对方结果导致死锁，或同一任务被两个 Agent 重复执行，你如何用任务账本和租约解决？
3. 设计 Agent 之间的消息 schema（任务 ID、所有权、状态、产物引用、超时），并说明如何压缩通信内容。

## 09.3 并行隔离与共享状态

`advanced` · 诊断：定位失败、设计对照并修正

先修：[09.2 通信、交接与任务账本](../modules/09.md#unit-09-2), [02.3 事务、幂等与一致性](../modules/02.md#unit-02-3), [10.4 不可信数据与工具安全](../modules/10.md#unit-10-4)

### 知识框架

- 任务上下文与共享事实的边界
- 数据库事务、版本和并发合并
- 文件/工作目录、Git worktree 和 artifact ownership
- 工具身份、权限、凭证与跨 Agent 泄漏
- 失败分支恢复、取消和资源回收

### 资源与阅读范围

[Deep Agents](https://docs.langchain.com/oss/python/deepagents/overview) — 学文件系统卸载、子任务隔离、规划与 harness 生命周期。

Subagents、filesystem/backend 与执行隔离文档。

### 动手任务

注入并发写冲突并验证隔离和合并策略。

### 自测题

1. 多个 Agent 并行修改代码时，为什么要用独立工作区或 git worktree？共享事实与任务私有上下文应如何区分？
2. 两个并行 Agent 同时更新共享状态，一个的结果覆盖了另一个，你如何用版本号或合并策略处理？
3. 为不同 Agent 分配身份和凭证时，如何防止一个 Agent 获得其他 Agent 的权限或泄露数据？

## 09.4 A2A 与跨服务 Agent 协作

`advanced` · 解释：讲清机制、边界与选择依据

先修：[09.2 通信、交接与任务账本](../modules/09.md#unit-09-2), [10.3 SDK 开发、认证与远程部署](../modules/10.md#unit-10-3)

### 知识框架

- 能力发现、Agent Card 与协作契约
- 消息、task 生命周期、进度和 artifact
- 同步/异步、streaming、重连与取消
- 跨服务身份、授权和信任边界
- A2A 与 MCP 分别连接 Agent 与工具

### 资源与阅读范围

[A2A Protocol](https://a2a-protocol.org/latest/) — Agent Card、任务、消息与跨服务协作。

协议概览、Agent Card、tasks、messages 和 artifacts。

### 动手任务

画一个跨组织 Agent 协作的数据/权限流。

### 自测题

1. 解释 A2A 协议中 agent card、task 生命周期和 artifact 的作用；A2A 与 MCP 的定位有什么不同？
2. 跨服务调用的远程 Agent 长时间没有响应，你的系统如何处理流式进度、重连和取消？
3. 两家公司的 Agent 通过 A2A 协作，身份认证、授权和信任边界应该如何设计？

## 09.5 协作评测与失败诊断

`advanced` · 诊断：定位失败、设计对照并修正

先修：[09.3 并行隔离与共享状态](../modules/09.md#unit-09-3), [11.4 实验、A/B 与不确定性](../modules/11.md#unit-11-4)

### 知识框架

- 相同模型、数据、工具与 token/时间预算
- 任务成功、子任务质量、协调/通信开销
- 重复劳动、角色漂移、错误共识和循环
- 单 agent、固定 workflow、协作与逐组件消融
- 长任务稳定性、可复现 trace 和负结果

### 资源与阅读范围

[Inspect AI](https://inspect.aisi.org.uk/) — 开源评估框架；学 dataset、solver、scorer 和 sandbox。

评测框架与多步骤任务/工具评分。

### 动手任务

证明一次协作设计在什么任务上值得使用。

### 自测题

1. 比较多 Agent 和单 Agent 时，为什么必须控制相同的模型、工具、token 和时间预算？
2. 多 Agent 系统中出现“虚假共识”或任务漂移，你如何从 trace 中识别并归因？
3. 设计一组消融实验，证明多 Agent 协作中究竟是哪一部分（分工、并行、互评）带来了收益。
