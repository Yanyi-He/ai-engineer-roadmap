# CS329Z / CS336 课程对照

本页说明本路线怎样对应 Stanford CS329Z 与 CS336：课程要求落在哪些单元、用什么实验产物证明，以及 CS336 中与应用/系统 AIE 相关的部分。课程材料核对于 2026-11-20；评测框架的操作见[实操指南](evaluation-playbook.md)。

## 要点

两门课涉及的主要技术类别都在知识图谱中。本路线重点落实的是：无框架机制实作、数据策展、环境任务与评分器验证、从模型评测到业务选型、资源核算，以及把基础知识接入项目的顺序。每个重点都对应可验证的实验产物，少数方向放在专项。

## CS329Z：怎样落实课程设计

[课程主页](https://cs329z.stanford.edu/)与[教学设计](https://cs329z.stanford.edu/logistics.html)给出系统构建、评测和长期项目的安排。本路线采用“独立机制→框架迁移→固定Agent评测→产品交付”的顺序：

1. L01建立模型接口，L13实现自己的执行循环与协议，L02补检索机制；随后迁移到LangGraph或DSPy等抽象。
2. L14固定Agent与任务环境，先确认任务可解、评分器可靠，再比较独立试次；修复Agent、环境或评分器时分别记录。
3. L15把真实失败转成有血缘的数据；提示、模型与数据优化使用独立测试。
4. 项目有proposal、基线、中期demo/review和最终复现；学习者解释实现与取舍，接受一项未见变更。

## 先修与学习路径

先修精确到单元，相关模块只作导航。四条[项目路线](dependency-order.md)自动展开先修，避免漏课或循环：

- 应用交付：API→评测→无框架Agent→授权工具/恢复→运行/验收；模型原理并行补齐。
- 企业知识：在应用基础上加入数据、检索、引用与维护。
- 本地推理与模型适配：小模型→资源核算→服务测量→数据策展→LoRA/训练验证。
- Agent平台：在应用基础上深化编排、工具目录、沙箱、记忆和协作；RL是显式可选分支。

SFT实作、GPU服务和复杂Multi-Agent实现按岗位选择。基础模型原理、评测、数据与系统知识仍保留。产品上线的公共先修使用API与通用后端，训练/自托管知识按选择展开。
