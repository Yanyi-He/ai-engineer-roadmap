## 00.2 From a business problem to an AI system

`core` · Design under constraints and defend tradeoffs

Prerequisites: [00.1 Role map and market interpretation](../modules/00.md#unit-00-1)

### Knowledge outline

- User, task, I/O, constraints and error costs
- Rules, classical ML, model APIs, RAG and agents
- Data, control, authorization and feedback flows
- Quality, latency, cost, reliability and UX
- Discovery→pilot→baseline→implementation→evaluation→deployment→operation

### Reading and scope

[Full Stack LLM Bootcamp](https://fullstackdeeplearning.com/llm-bootcamp/) — Complete free recordings/materials; use 2023 content for principles and current docs for APIs.

Project design, model choice, evaluation and productization.

### Practical evidence

Produce a task card, an end-to-end diagram and acceptance criteria.

### Self-check

1. For a “classify support tickets and draft replies” request, which questions do you ask first to pin down the task, inputs and outputs, error costs and acceptance criteria?
2. When are rules or classical ML a better fit than an LLM? Give an example where adding an LLM made things worse and explain why.
3. Sketch the data, control and authorization flows for an internal document Q&A system, and list exit criteria for each stage from pilot to launch.
