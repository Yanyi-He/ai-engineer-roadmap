## 15.1 JD 映射与作品规划

`core` · 设计：在约束下选择架构并论证取舍

先修：[00.1 岗位地图与市场读法](../modules/00.md#unit-00-1), [00.2 从业务问题到 AI 系统](../modules/00.md#unit-00-2)

### 知识框架

- 目标国家、岗位族、行业和 level
- 共同要求、专项要求与能力缺口
- 能力→实现→测试→结果→设计判断的证据链
- 项目范围、数据与用户可得性
- 个人贡献、团队协作和可验证结果

### 资源与阅读范围

[Tech Interview Handbook](https://www.techinterviewhandbook.org/) — 免费求职全流程手册：简历、准备计划、编程面试、行为面试与谈薪。

简历、准备计划与面试流程章节；能力—作品映射使用本仓库岗位总述与 JD 矩阵。

### 动手任务

用真实 JD 制作能力—作品覆盖矩阵。

### 自测题

1. 把一份目标 JD 拆成通用要求和专项要求；如何判断你的差距是“需要学”还是“缺证据”？
2. 你的作品集项目与目标岗位 JD 匹配度不高，如何调整项目范围或补充证据，而不是从头再做？
3. 为目标岗位写一张“能力→实现→测试→结果→判断”表，至少覆盖 3 项核心能力。

### 知识框架

- README、demo、架构、API、任务卡与数据卡

### 资源与阅读范围

### 动手任务

让独立评审人复现作品并提出一个新需求。

### 自测题

1. 一份能让面试官 5 分钟内信服的项目 README 应包含哪些部分？为什么要写失败案例和局限？
2. 面试官 clone 了你的仓库却跑不起来，列出常见原因（依赖未锁定、密钥、数据缺失）及预防办法。
3. 为你的项目设计可复现的评测命令和结果报告：基线、消融、逐例结果和成本。

## 15.3 编程与 AI 应用面试

`core` · 诊断：定位失败、设计对照并修正

先修：[01.4 算法与数据结构的工程用法](../modules/01.md#unit-01-4), [11.2 分层指标与 Agent 轨迹评测](../modules/11.md#unit-11-2), [14.2 系统架构与多租户产品](../modules/14.md#unit-14-2)

### 知识框架

- Python/SQL/API/并发/数据库基础题
- LeetCode 高频题型（哈希、双指针、堆、图/拓扑、DP）与限时解题
- RAG/Agent/Multi-Agent/MCP 的设计取舍
- 数据与指标、实验、成本、延迟和规模估算
- 故障定位、权限、回滚和线上反馈

### 资源与阅读范围

[Chip Huyen: Introduction to Machine Learning Interviews](https://huyenchip.com/ml-interviews-book/) — 免费在线面试书：ML 岗位类型与招聘流程，以及数学、CS、ML 工作流题库；LLM 专题用本路线 04–07 单元补充。

岗位与面试流程章节及 CS/ML 工作流题库；RAG 与 Agent 取舍题用 06–07 单元自测，编程题按 01.4 题型限时练习。

### 动手任务

完成一轮模拟面试：两道限时编程题、一道 SQL 题和一组 RAG/Agent 取舍问答，记录卡壳点并补课。

### 自测题

1. 限时 30 分钟实现一个带 TTL 和容量上限的缓存，或用堆求流式 top-k，边写边说明复杂度和边界用例。
2. 面试官问“你的 RAG 系统召回率低怎么办”，给出一个结构化的诊断思路，而不是罗列技巧。
3. 如何回答“什么时候不该用 Agent”？结合成本、延迟、可测试性和风险给出你的判断框架。

## 15.4 项目答辩与入职交付

`core` · 设计：在约束下选择架构并论证取舍

先修：[15.2 完整项目包与开源呈现](../modules/15.md#unit-15-2), [15.3 编程与 AI 应用面试](../modules/15.md#unit-15-3)

### 知识框架

- 问题、约束、方案、取舍、结果和个人贡献
- 解释失败、负结果、复现和后续假设
- 需求澄清、估算、PR/code review 和文档
- 跨团队沟通、演示、交接和维护
- 面对未见需求的修改与现场诊断
- 解释一篇相关论文/系统的证据、假设和适用边界，用同伴 review 发现评测或实现缺口

### 资源与阅读范围

[Design Docs at Google](https://www.industrialempathy.com/posts/design-docs-at-google/) — 设计文档的结构、目标/非目标、备选方案与评审方式；用于项目答辩与入职后的方案沟通。

全文：设计文档结构、备选方案与评审；事故复盘对照 Google SRE 书的 Postmortem 章节。

### 动手任务

完成一次设计答辩、一条隐藏故障和一次小变更。

### 自测题

1. 用 3 分钟介绍你的项目：问题、约束、关键选择、结果和你个人的贡献。
2. 面试官质疑你的评测结果“可能是在测试集上过拟合”，你如何用证据回应？
3. 入职后接手一个没有文档的 AI 系统，前两周你会如何摸清现状、估算工作量并与团队对齐？

## 15.5 LLM 原理面试与手写实现

`core` · 实现：独立完成小型实现并验证行为

先修：[04.2 Transformer 完整计算链](../modules/04.md#unit-04-2), [04.4 解码与结构化生成](../modules/04.md#unit-04-4), [01.4 算法与数据结构的工程用法](../modules/01.md#unit-01-4)

### 知识框架

- 高频原理题：attention 复杂度、KV cache、RoPE、MHA/GQA/MLA、Pre-Norm 与 RMSNorm
- 训练与对齐题：交叉熵/困惑度、LoRA 原理与参数量、SFT/DPO/PPO/GRPO 差异
- 手写：多头因果注意力、LayerNorm/RMSNorm、数值稳定的 softmax
- 手写：top-k/top-p/temperature 采样、BPE merge、LoRA 线性层
- 参数量、显存与 FLOPs 的口算估计
- 中国“手撕”与北美 live coding 的形式差异；边写边讲与边界测试

### 资源与阅读范围

[Build a Large Language Model (From Scratch): Code](https://github.com/rasbt/LLMs-from-scratch) — Raschka 的配套代码：从 tokenizer、注意力到 GPT、预训练与微调逐章实现，适合手写练习。

第 2–7 章与附录 E（LoRA）：tokenizer、注意力、GPT、预训练与微调；不看答案独立重写核心组件。

### 动手任务

30 分钟内不查资料手写多头因果注意力与 top-p 采样并通过自写测试；整理 20 道原理题的口述答案。

### 自测题

1. 手写多头因果自注意力（含 mask 和缩放），说明时间与空间复杂度，以及 KV cache 如何改变推理开销。
2. 解释 RMSNorm 与 LayerNorm 的区别、pre-norm 为什么训练更稳定，以及 GQA 为什么能减小 KV cache。
3. 不查资料估算：7B 模型的 FP16 权重占多少显存？LoRA rank=8 作用于所有注意力投影时大约增加多少参数？

## 15.6 生成式 AI 系统设计面试

`core` · 设计：在约束下选择架构并论证取舍

先修：[14.2 系统架构与多租户产品](../modules/14.md#unit-14-2), [11.2 分层指标与 Agent 轨迹评测](../modules/11.md#unit-11-2), [05.5 模型路由、缓存与成本](../modules/05.md#unit-05-5)

### 知识框架

- 答题框架：澄清需求与指标→基线→架构→数据/检索→模型→评测→上线→迭代
- 平台组件：上下文增强、护栏、路由/网关、缓存、Agent 编排与观测
- 经典题：企业知识助手、客服工单 Agent、代码 Agent、文档抽取流水线、LLM 网关
- 容量与成本估算：QPS、token 量、缓存命中、GPU/API 费用
- 失败模式与追问：幻觉、越权、延迟尖峰、模型升级回归
- 取舍表达：先给可行方案，再讲替代方案、代价与验证方式

### 资源与阅读范围

[Chip Huyen: Building a Generative AI Platform](https://huyenchip.com/2024/07/25/genai-platform.html) — 按组件逐层构建生成式 AI 平台：上下文增强、护栏、路由/网关、缓存、Agent 与观测；适合作系统设计题骨架。

全文：按组件逐层加入的平台架构；通用分布式部分对照 System Design Primer。

### 动手任务

45 分钟内设计一个企业 Agent，画出架构与数据流并估算成本，在面试官改变约束后调整方案。

### 自测题

1. 按“澄清需求与指标→基线→架构→数据/检索→模型→评测→上线→迭代”的框架，在 45 分钟内设计一个企业知识助手。
2. 估算一个日活 10 万、每人每天对话 10 次的助手的 token 用量和月度 API 成本，并说明缓存如何改变结果。
3. 面试官追问“上线后发现模型越权访问数据”或“升级模型后质量回退”，你的设计如何应对？

## 15.7 简历、投递节奏与行为面试

`core` · 设计：在约束下选择架构并论证取舍

先修：[15.1 JD 映射与作品规划](../modules/15.md#unit-15-1)

### 知识框架

- 中国校招节奏：暑期实习、秋招提前批/正式批、春招与内推
- 北美流程：recruiter screen、OA、电话面、onsite loop 与内推
- 一页简历：项目要点写成“问题—方法—量化结果”，与目标 JD 关键词对齐
- GitHub、作品集与技术文章：让面试官 5 分钟内看到证据
- 行为面试：STAR 故事库（冲突、失败、影响力、模糊需求）
- 投递追踪、复盘、offer 比较与谈薪基础

### 资源与阅读范围

[Tech Interview Handbook](https://www.techinterviewhandbook.org/) — 免费求职全流程手册：简历、准备计划、编程面试、行为面试与谈薪。

Resume、Behavioral interviews 与 Negotiation 章节；中国校招时间以目标公司招聘官网公告为准。

### 动手任务

按两份目标 JD 改写简历，准备 6 个 STAR 故事，并建立投递追踪表记录每轮反馈。

### 自测题

1. 把一段项目经历改写成“问题—方法—可测量结果”的简历条目，并对齐目标 JD 的关键词。
2. 准备一个 STAR 故事：一次失败或与同事意见冲突的经历，说明你做了什么、学到了什么。
3. 列出你目标市场（国内校招、社招或北美）的投递时间线和面试流程，并设计投递跟踪和复盘方法。
