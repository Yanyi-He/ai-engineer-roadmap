## 07.1 Workflow 与 Agent 的选型

`core` · 设计：在约束下选择架构并论证取舍

先修：[05.3 结构化输出与工具执行](../modules/05.md#unit-05-3)

### 知识框架

- 确定流程、动态决策和混合架构
- routing、parallelization、orchestrator-workers 和 evaluator loop
- 自主性、可控性、任务复杂度和可验证性
- 模型/上下文/工具/runtime 的数据与控制边界
- 单次调用、长任务、用户等待和成本
- prompt chaining、routing、parallelization、orchestrator-workers、evaluator-optimizer 逐一映射任务

### 资源与阅读范围

[Anthropic: Building Effective Agents](https://www.anthropic.com/research/building-effective-agents) — 完整免费设计文章；工作流、路由、并行、评审优化的选择依据。

全文与五种可组合工作流模式。

### 动手任务

对同一业务任务设计规则、workflow 和 agent 三版。

### 自测题

1. 解释 workflow 与 agent 的区别；链式调用、路由、并行、编排者—工作者和评估者—优化者这五种模式各适合什么任务？
2. 团队用全自主 Agent 实现了一个本可以用固定流程完成的任务，结果不稳定且难以测试，你会如何重构？
3. 针对“处理退货申请”的需求，论证哪些步骤用固定流程、哪些交给模型决策，以及如何控制成本和等待时间。

## 07.2 推理—行动循环与规划

`core` · 实现：独立完成小型实现并验证行为

先修：[07.1 Workflow 与 Agent 的选型](../modules/07.md#unit-07-1)

### 知识框架

- ReAct、Plan-and-Execute、ReWOO 和 CodeAct
- 目标拆分、计划修订、观察和环境状态
- 工具选择、参数生成、执行与结果验证
- 终止、最大步数、循环检测与预算
- 反思/修复的触发条件与额外开销

### 资源与阅读范围

[Hugging Face Agents Course](https://huggingface.co/learn/agents-course/en/unit0/introduction) — 公开完整单元、代码和项目，覆盖多个框架与 agentic RAG。

Agent 基本循环、工具与设计模式单元。

### 动手任务

实现一个有明确终止条件的只读工具 agent。

### 自测题

1. 比较 ReAct、plan-and-execute、ReWOO 和 CodeAct 的控制流程，以及它们在步数、成本和容错上的差异。
2. Agent 陷入反复调用同一工具的循环，你如何检测循环并设计终止条件和预算？
3. 不用框架手写一个最小的 ReAct 循环：解析工具调用、执行、把观察结果写回上下文，并在完成时停止。

- Action/Observation、schema、错误和超时契约
- 工作目录、artifact、shell/browser/computer 工具接口
- 预算、权限、事件日志和运行生命周期
- 可重放环境、任务 reset 与版本 manifest

### 资源与阅读范围

[LangChain Academy: Introduction to Deep Agents](https://academy.langchain.com/courses/foundation-introduction-to-deepagents) — 官方新完整课，覆盖执行环境、上下文、委派和人工参与；不要求购买托管部署。

### 自测题

1. 说明 Agent harness 中策略（模型）、控制器、环境和工具注册表各自的职责，为什么要把它们分开？
2. 工具超时或返回超大输出时，harness 应如何把错误或截断后的观察结果反馈给模型？
3. 设计一份可重放的 Agent 运行记录：需要记录哪些版本信息和事件，才能在出问题后复现这次运行？

## 07.4 状态、持久化与故障恢复

`core` · 诊断：定位失败、设计对照并修正

先修：[07.3 Harness 职责与 Agent—环境接口](../modules/07.md#unit-07-3), [02.3 事务、幂等与一致性](../modules/02.md#unit-02-3), [02.4 缓存、队列与后台任务](../modules/02.md#unit-02-4)

### 知识框架

- 状态 schema、事件日志、checkpoint 和运行 ID
- 持久化与外部副作用的提交边界
- 幂等、outbox、lease/fencing 和重投递
- 暂停、审批、恢复、重放与版本变化
- 超时、部分失败、补偿和结果未知时的对账

### 资源与阅读范围

[LangGraph Overview and Guides](https://docs.langchain.com/oss/python/langgraph/overview) — 以维护者文档为 API 真值，重点 persistence、interrupts 与 durable execution。

Persistence、durable execution、interrupts 和 time travel。

### 动手任务

### 自测题

1. 解释 Agent 状态的 checkpoint 与外部系统提交的区别；为什么“状态已保存”不代表“外部操作已完成”？
2. Agent 在发出邮件之后、保存状态之前崩溃，恢复后又发了一次邮件。你如何用幂等键或 outbox 修复？
3. 设计一个需要人工审批的 Agent 流程：暂停、审批、恢复，以及审批期间输入被修改时如何处理。

### 知识框架

- 巩固触发、重复经验合并、冲突、遗忘和回滚

- 参数记忆与上下文记忆：权重适配和检索/写入在更新、撤回、费用上的不同边界

### 资源与阅读范围

[Stanford CS329Z: Engineering AI Agents](https://cs329z.stanford.edu/) — Agent 工程主干课程：按已发布材料串联框架、数据、优化、评测与安全。

### 自测题

1. 解释分层记忆（热层/冷层、分页）与上下文窗口管理的关系，以及 MemGPT 类设计的基本思路。
2. Agent 从过往轨迹中总结的“经验”被污染，导致后续任务持续出错，你如何发现并回滚？
3. 设计一个实验：在相同 token 预算下比较全量历史、向量检索记忆和分层记忆，并分别测量写入、检索和任务结果。

## 07.9 代码 Agent 与 Agent—Computer Interface

`advanced` · 实现：独立完成小型实现并验证行为

先修：[07.3 Harness 职责与 Agent—环境接口](../modules/07.md#unit-07-3), [10.5 代码、浏览器与沙盒](../modules/10.md#unit-10-5), [11.8 环境型 Benchmark 与评测器验证](../modules/11.md#unit-11-8)

### 知识框架

- 任务描述→仓库/工作区→定位→编辑→执行测试→提交 artifact 的闭环
- shell、文件编辑、搜索与浏览器接口的可用性和可观察性
- 状态化工具、输出截断、工作目录、长命令、错误与恢复
- repo revision、依赖、测试环境和干净 reset；无网络的安全小任务
- patch 是否正确、测试是否充分、环境是否被修改或绕过
- 接口消融、工具反馈质量与模型能力的区分

### 资源与阅读范围

[CS329Z: Evaluation Task Assignment](https://github.com/cs329z/assignment2-evals) — 公开评测任务构建练习，配合自建 benchmark。

已公开 HW2 示例与课程列出的 SWE-agent 阅读；11 月 30 日讲座截至审阅日尚未授课。

### 动手任务

在小型离线仓库完成一个修复任务，保存 patch、测试、轨迹和干净重放，比较两种工具观察格式。

### 自测题

1. 什么是 agent–computer interface（ACI）？为什么 SWE-agent 等工作表明工具接口设计和模型能力同样重要？
2. 代码 Agent 通过修改测试让测试通过，你如何在环境和评测设计上防止这种作弊？
3. 设计代码 Agent 的工作区：仓库版本、依赖、长时间运行的命令、输出截断，以及每个任务的干净重置。
