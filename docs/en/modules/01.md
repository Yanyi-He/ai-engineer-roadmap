### Knowledge outline

- Objects, mutability, references, copying and collections
- Parameters, scope, closures, decorators and context managers
- Classes, dataclasses, protocols, composition and interfaces
- Exceptions, cleanup, logging and error propagation
- Iterators, generators, file streams and memory

### Reading and scope

[Python Tutorial](https://docs.python.org/3/tutorial/) — Complete maintainer tutorial; practise exceptions, iterators, modules and concurrency boundaries.

Tutorial: collections, functions, modules, classes, exceptions, iterators and generators.

### Practical evidence

Implement streaming document cleaning and explain memory/error boundaries.

### Self-check

1. Explain how mutable default arguments, shallow copies and deep copies behave in Python, and write an example where a shared reference causes a bug.
2. A script processing a large file keeps growing in memory. How would you rewrite it with generators, streamed reads and context managers, and verify the memory profile?
3. Design a swappable LLM client interface with a dataclass or Protocol, and explain why you chose composition over inheritance.

## 01.3 Async, concurrency and cancellation

`core` · Diagnose failures, compare and repair

Prerequisites: [01.1 Python language and data model](../modules/01.md#unit-01-1)

### Knowledge outline

- Event loops, coroutines, tasks, await and blocking I/O
- Threads/processes/coroutines, GIL and CPU work
- Concurrency limits, pools, queues and backpressure
- Deadlines, timeout, cancellation and cleanup
- Races, shared state, locks and error aggregation

### Reading and scope

[Python asyncio: Coroutines and Tasks](https://docs.python.org/3/library/asyncio-task.html) — Official asyncio task reference: Task, TaskGroup, timeouts, cancellation and shield; the API source of truth for bounded concurrency and cleanup.

Coroutines and Tasks: Task, TaskGroup, timeouts, cancellation and shield; then asyncio queues and synchronization primitives.

### Practical evidence

Bound a slow model client and diagnose leaked capacity after cancellation.

### Self-check

1. Explain how the event loop, coroutines and tasks relate. Why does calling a synchronous HTTP library inside an async function slow the whole service?
2. Firing 100 concurrent model API calls produces many 429s and timeouts. How would you rework the calls with a semaphore, a queue and an overall deadline?
3. When a user cancels mid-request, how should downstream model calls and database writes be cancelled or cleaned up? Describe how cancellation propagates in asyncio and what belongs in finally.

2. To deduplicate, merge and take the top-k of results from several retrievers at scale, which data structures would you use and at what complexity?
3. Given tasks with dependencies (such as agent subtasks), implement a topological sort with cycle detection. How should a cycle be reported to the user?

## 01.5 Testing, debugging and profiling

`core` · Diagnose failures, compare and repair

Prerequisites: [01.1 Python language and data model](../modules/01.md#unit-01-1), [01.2 Types, schemas and configuration](../modules/01.md#unit-01-2)

### Knowledge outline

- Unit/integration/contract/end-to-end tests
- Fixtures, dependency fakes, seeds and fault injection
- Breakpoints, stacks, logs and CPU/memory profiles
- Formatting, typing, static checks and CI
- AI-assisted review, test validity and upgrade regression

### Reading and scope

[The Missing Semester](https://missing.csail.mit.edu/) — MIT course with public exercises on shell, Git, debugging and performance.

Debugging, profiling, Git and testing tools.

### Practical evidence

Diagnose a concurrency/memory fault and submit reproduction plus repair rationale.

### Self-check

1. What does each of unit, integration, contract and end-to-end tests verify? For a function that calls an LLM, which parts get test doubles and which need real calls?
2. A test fails intermittently. How do you determine whether the cause is randomness, concurrency, an external dependency or timing?
3. An AI assistant wrote tests that all pass. How do you check they actually test something, for example with mutation testing or by deliberately breaking the implementation?

## 01.7 AI-assisted programming and coding-agent workflows

`core` · Diagnose failures, compare and repair

Prerequisites: [01.5 Testing, debugging and profiling](../modules/01.md#unit-01-5), [01.6 Environment, Linux and collaboration](../modules/01.md#unit-01-6)

### Knowledge outline

- Capability limits, permission modes and cost of tools such as Claude Code, Codex and Cursor
- Explore and plan before coding: task decomposition, acceptance criteria and small commits
- AGENTS.md/CLAUDE.md, skills and MCP configuration: turning repository conventions into reusable context
- Verifying generated code: tests first, diff review, dependency/security checks and hallucinated APIs
- Sandboxes, secrets and production access; human confirmation for irreversible actions
- Measuring productivity and AI-allowed interviews: explaining your own judgment rather than the assistant’s output
- AI-driven testing and code review built into team standards; fluent but not dependent: read code, debug and explain designs without an assistant

### Reading and scope

[Claude Code: Best Practices](https://code.claude.com/docs/en/best-practices) — Official coding-agent practice guide: explore before planning, context files, permissions and verification loops; the methods transfer to other assistants.

Full guide: explore–plan–code–commit workflow, context files, permissions and verification; compare repository conventions with AGENTS.md.

### Practical evidence

Ship a small tested feature with a coding agent and keep the plan, diff-review notes and the errors you corrected yourself.

### Self-check

1. Before handing a feature to a coding agent, what context do you prepare (AGENTS.md, acceptance criteria, tests)? Why does exploring and planning before coding raise the success rate?
2. Agent-generated code calls a library function that doesn’t exist, and the agent also edited the tests. How would you catch this in review?
3. In an AI-allowed interview, the interviewer asks why the code is written this way. How do you show your own judgment rather than repeating the assistant’s output?
