# 入门诊断

用下面七项判断自己从哪里开始，大约花一两个小时。每项都要动手：写一段能跑的代码、算一个小例子，或者口头讲清楚。可以查官方文档，也可以拿已有作品代替。哪项做不出来，就从对应单元开始学。

| 诊断 | 要做出来的事 | 对应单元 |
|---|---|---|
| D0 编程 | 读文件、处理异常、拆分函数和模块；写测试，并修好一个失败的测试 | 01.1–01.2、01.4–01.6 |
| D1 服务 | 校验 JSON 输入；给慢依赖设超时并能取消；统一错误返回；讲清 async 和并行的区别 | 01.3、02.1、05.1 |
| D2 数据 | 写 SQL 并建索引；两个客户端同时更新一条记录时，用事务、唯一约束或版本号避免互相覆盖 | 02.2–02.4 |
| D3 工程 | 从干净目录把项目跑起来，管理依赖和配置，用 Git 协作，排查 Linux 上的进程和网络问题 | 01.5–01.6、02.6 |
| D4 数学/ML | 手算两个向量的余弦相似度、softmax 和交叉熵；讲清训练集、测试集和过拟合 | 03 |
| D5 模型 | 讲清 token → embedding → attention → logits 的过程并标出张量形状，说出训练和推理的区别 | 04 |
| D6 评测 | 给 10 道题定好标签，分出 dev 和 test，用配对比较两个系统 | 11.1–11.4 |

D0–D3 都过了，就直接从模型 API 应用开始；D4–D5 可以边做应用边补；D6 在第一次优化检索之前补上。把跳过的单元和还没解决的问题记下来，之后复习用。完整范围见[知识树](knowledge-tree.md)，时间安排见[学习路径](learning-path.md)。
