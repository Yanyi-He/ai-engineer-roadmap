## 01.3 异步、并发与取消

`core` · 诊断：定位失败、设计对照并修正

先修：[01.1 Python 语言与数据模型](../modules/01.md#unit-01-1)

### 知识框架

- event loop、协程、task、await 与阻塞 I/O
- 线程/进程/协程的选择；GIL 与 CPU 密集任务
- 并发上限、信号量、连接池、队列与背压
- deadline、超时、取消传播、任务清理
- 竞态、共享状态、锁与异步错误聚合

### 资源与阅读范围

[Python asyncio: Coroutines and Tasks](https://docs.python.org/3/library/asyncio-task.html) — 官方 asyncio 任务文档：Task、TaskGroup、timeout、取消与 shield，是并发上限和取消清理的 API 真值。

Coroutines and Tasks 全文：Task、TaskGroup、timeout、取消与 shield；再读 asyncio queues 与同步原语。

### 动手任务

给慢模型客户端加并发和排队上限，复现取消后资源泄漏。

### 自测题

1. 解释事件循环、协程和 Task 的关系；为什么在 async 函数里调用同步 HTTP 库会拖慢整个服务？
2. 并发调用 100 次模型 API 时出现大量 429 和超时，你如何用信号量、队列和总截止时间重写调用逻辑？
3. 用户中途取消请求后，下游的模型调用和数据库写入应如何取消或清理？说明 asyncio 中取消如何传播、finally 里该做什么。

## 01.7 AI 辅助编程与 Coding Agent 工作流

`core` · 诊断：定位失败、设计对照并修正

先修：[01.5 测试、调试与性能分析](../modules/01.md#unit-01-5), [01.6 开发环境、Linux 与协作](../modules/01.md#unit-01-6)

### 知识框架

- Claude Code、Codex、Cursor 等工具的能力边界、权限模式与费用
- 先探索/计划再编码：任务拆分、验收标准与小步提交
- AGENTS.md/CLAUDE.md、Skills 与 MCP 配置：把仓库约定变成可复用上下文
- 验证生成代码：测试先行、diff 审阅、依赖与安全检查、虚构 API
- 沙箱、密钥与生产权限；不可逆操作的人工确认
- 效率度量与可用 AI 的面试：讲清自己的判断而非复述助手输出
- AI 驱动的测试与代码评审，沉淀为团队规范；熟练使用但不依赖：没有 AI 也能读代码、排障和解释设计

### 资源与阅读范围

[Claude Code: Best Practices](https://code.claude.com/docs/en/best-practices) — Coding Agent 官方实践指南：先探索再计划、上下文文件、权限与验证循环；方法可迁移到其他编码助手。

全文：探索—计划—编码—提交流程、上下文文件、权限与验证；仓库级约定格式对照 AGENTS.md。

### 动手任务

用 Coding Agent 完成一个带测试的小功能，保留计划、diff 审阅记录与自己修正的错误。

### 自测题

1. 把一个功能交给 Coding Agent 之前，你会准备哪些上下文（AGENTS.md、验收标准、测试）？为什么“先探索和规划再写代码”能提高成功率？
2. Agent 生成的代码调用了一个不存在的库函数，而且顺手改了测试。你在 review 时如何发现这类问题？
3. 在允许使用 AI 的面试中，面试官问“这段代码为什么这样写”，你如何展示自己的判断，而不是复述助手的输出？
