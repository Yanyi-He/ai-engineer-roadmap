# 毕业评审：能否独立承担应用AIE工作

学完链接不等于形成能力。单元级自测见[自测题清单](self-check.md)；本页评审的是完整作品。这是本路线的作品评审标准，不是雇主统一认证，也不保证录用。建议由没有参与实现的人，从干净环境运行作品并提出一项未预告变更；完全自评只能记录为自评。

| 能力 | 至少达到的独立表现 | 证据 |
|---|---|---|
| 定义问题 | 把业务痛点转成任务、非目标、错误成本与验收条件；解释为何需要LLM | 任务说明、基线、用户反馈或明确代理标签 |
| 构建系统 | 独立实现数据→模型/检索→工具→结果；解释schema、状态、事务和权限 | 可运行仓库、架构图、契约及关键代码 |
| 设计实验 | 固定dev/test、标签和版本；分层诊断；做一项公平消融并承认负结果 | 原始逐题结果、数据卡、错误分析 |
| 运营与恢复 | 在限流、重复投递、崩溃和授权失效下表现有边界；演练回滚 | 运行手册、故障注入、脱敏trace、回滚记录 |
| 模型基本功 | 本地跑一个模型，解释量化、token、上下文和性能测量条件 | 权重revision、硬件、质量/延迟/内存结果 |
| 沟通与判断 | 面对新需求能修改设计；指出何时不用agent、何时不该上线 | 设计答辩、决策记录、下一步假设 |

每项0–3级：0无法运行/解释，1依赖教程复现，2能独立修改并诊断，3能处理未见约束并解释取舍。**本路线出口要求六项均达到2，且关键边界无未处理失败。** 这是作者定义的审查规则，没有假装来自招聘统计。

关键边界：不能编造实验结果；不能把公开测试集反复调参结果称为盲测；不能跨用户泄漏；执行型任务不能在未授权时产生效果；失败必须可见；必须能从文档复现。高风险领域还需相应领域评审，工程实验不能代替它。

建议评审流程：20分钟任务/架构说明；30分钟现场定位一条隐藏失败；30分钟做一个小变更；20分钟审查实验和取舍。预留3类隐藏题：过期文档、更改后的审批动作、外部提交后进程死亡。按实际独立表现记录结果，不按背出框架名打分。

通过代表具备一项可展示的应用AIE作品和一组独立能力证据；没有验证跨团队生产规模、长周期维护或高级算法研究能力。若要申请后训练/推理平台岗位，还应完成对应专项实验，不能凭应用项目替代。

评审还应抽查[L13无框架内核、L14环境/评分器和L15数据策展](labs.md)，按作品涉及的能力选择检查。训练与自托管实验按所申请方向评审；中期与最终复核应由不同于实现者的人留下记录。

测评操作见[Ragas与回归指南](evaluation-playbook.md)，用L16/L17把指标、评测器和CI接到作品中。
