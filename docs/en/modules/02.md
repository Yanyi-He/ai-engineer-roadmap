## 02.1 HTTP APIs and streaming

`core` · Implement a small system and verify behavior

Prerequisites: [01.2 Types, schemas and configuration](../modules/01.md#unit-01-2), [01.3 Async, concurrency and cancellation](../modules/01.md#unit-01-3)

### Knowledge outline

- HTTP semantics, REST, pagination, OpenAPI and versions
- DNS/TCP/TLS, proxies, reuse and connection deadlines
- SSE/WebSocket, interruptions, heartbeat and reconnect
- Request IDs, idempotency, errors and deadlines
- Uploads/downloads, object references and large-file limits

### Reading and scope

[FastAPI Tutorial](https://fastapi.tiangolo.com/tutorial/) — Maintainer tutorial covering types, dependencies, async, authentication and tests.

Requests, dependencies, errors, authentication, testing and streaming responses.

### Practical evidence

Build an async task API with SSE replay.

### Self-check

1. Compare SSE and WebSocket for streaming LLM output, including how each behaves with proxies, timeouts and reconnection.
2. Users report streamed answers often cut off around 30 seconds. Which layers would you check: reverse-proxy buffering, timeouts, heartbeats, load balancers?
3. Design an “upload a document and parse it asynchronously” API: request, status polling, idempotency key, error codes and large-file limits.

3. Write SQL that counts daily requests and failure rate per tenant over the last 7 days and uses a window function to return each tenant’s three worst days.

## 02.3 Transactions, idempotency and consistency

`core` · Diagnose failures, compare and repair

Prerequisites: [02.2 SQL, modeling and indexes](../modules/02.md#unit-02-2)

### Knowledge outline

- Isolation, lost updates and optimistic/pessimistic locking
- Constraints, CAS and payload-bound idempotency
- At-least-once delivery, ordering and deduplication
- Outboxes, compensation and ambiguous external commits
- Event/processing time, revisions and audit

### Reading and scope

[AWS Builders Library: Idempotent APIs](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/) — Substantial engineering article on retries, duplicate requests and side effects.

Full article with PostgreSQL concurrency control and version checks.

### Practical evidence

Reproduce a crash between external effect and local commit.

### Self-check

1. Explain the lost-update problem and how optimistic locking, pessimistic locking and database constraints each prevent it.
2. An agent’s “create refund” tool call times out and you don’t know whether the external system executed it. How do you design idempotency keys and reconciliation to avoid a double refund?
3. Explain how the outbox pattern keeps a database write and a published message consistent, and write consumer-side deduplication under at-least-once delivery.

## 02.4 Caches, queues and workers

`core` · Diagnose failures, compare and repair

Prerequisites: [01.3 Async, concurrency and cancellation](../modules/01.md#unit-01-3), [02.3 Transactions, idempotency and consistency](../modules/02.md#unit-02-3)

### Knowledge outline

- Cache patterns, TTL, invalidation and stampedes
- Acknowledgment, retries, dead letters and delayed tasks
- Worker pools, leases, heartbeat and fencing
- Rate limits, circuit breakers, backpressure and fairness
- Task state, progress, cancellation and replayable events

### Reading and scope

[System Design Primer](https://github.com/donnemartin/system-design-primer) — Widely used free system-design guide: cache patterns, asynchronous queues, back pressure and consistency/availability tradeoffs; also a common base for design interviews.

Cache, asynchronism, back-pressure and availability/consistency sections; compare retries and idempotency with the AWS Builders Library.

### Practical evidence

Race two workers and prevent a stale worker overwriting results.

### Self-check

1. Explain cache breakdown (a hot key expiring), cache avalanche and cache penetration, and how to mitigate each.
2. A background parsing job occasionally runs twice and leaves duplicate chunks in the index. How do you investigate acknowledgment, leases and idempotent writes?
3. Design workers for long-running LLM batch jobs: retries, dead letters, progress reporting, cancellation and fair scheduling so one tenant cannot hog capacity.

## 02.5 Identity, authorization and tenancy

`core` · Implement a small system and verify behavior

Prerequisites: [02.1 HTTP APIs and streaming](../modules/02.md#unit-02-1), [02.2 SQL, modeling and indexes](../modules/02.md#unit-02-2)

### Knowledge outline

- Sessions, JWT, OAuth2/OIDC and service identity
- Authentication/authorization, RBAC/ABAC and least privilege
- Tenant/user/project filtering and trusted principals
- Secret storage, rotation, audit and redaction
- SSRF, egress, validation and dependency security

### Reading and scope

[OWASP Cheat Sheet Series](https://cheatsheetseries.owasp.org/) — OWASP-maintained practice sheets with separate entries for authentication, authorization, sessions, JWT, secrets management and SSRF prevention.

Authentication, Authorization, Session Management, JSON Web Token, Secrets Management and SSRF Prevention sheets.

### Practical evidence

Exercise all read paths with two tenants and a forged user_id.

### Self-check

1. Explain authentication versus authorization, and what the OAuth2 authorization-code flow and OIDC each provide.
2. In a RAG system, a user in tenant A retrieved a tenant B document. Which layers could be at fault, and what test would prevent a regression?
3. An agent must call a third-party API on a user’s behalf. How do you handle the tokens: storage, scopes, rotation, auditing and log redaction?

## 02.8 Java/Spring AI and enterprise system integration

`advanced` · Implement a small system and verify behavior

Prerequisites: [02.1 HTTP APIs and streaming](../modules/02.md#unit-02-1), [02.5 Identity, authorization and tenancy](../modules/02.md#unit-02-5)

### Knowledge outline

- Spring Boot service structure, dependency injection, configuration and observability basics
- Spring AI ChatClient, structured output, tool calling and advisors
- RAG, vector stores and MCP client/server support in Spring AI and LangChain4j
- Boundaries between Python model services and Java business systems: HTTP/gRPC, queues and schema contracts
- Enterprise integration: SSO/permissions, transactions, auditing and existing microservice governance
- Equivalent capabilities and selection in C#/.NET and Go

### Reading and scope

[Spring AI Reference](https://docs.spring.io/spring-ai/reference/) — Java enterprise elective: integrate models and tools into existing Spring services.

ChatClient, structured output, tool calling, advisors, RAG and MCP chapters; compare LangChain4j as a second framework.

### Practical evidence

Add a tool-calling, audited Q&A endpoint to an existing Java service with Spring AI and document its boundary with a Python service.

### Self-check

1. Which LLM-application concepts do Spring AI’s ChatClient, advisors and tool calling correspond to? How does it compare with LangChain4j?
2. Core business logic lives in Java microservices and model capabilities in a Python service. Describe the contracts, timeouts and error handling when integrating them over HTTP/gRPC or a message queue.
3. When adding a RAG assistant to an enterprise system with existing SSO and permissions, at which layer do permission filtering, transactions and auditing belong?
