# 项目实践：围绕企业任务完成端到端交付

题目从招聘交付要求、常见业务场景和开源系统机制提炼。选一个主要项目，把基础实验接入同一产品，再增加一个有实测结果的纵深。数据采用公开许可资料、可公开的自建数据或明确授权的数据。

## P1 企业知识服务

**任务：** 让不同角色查询制度、产品手册或技术文档，回答带证据，资料可以更新和撤回。公开技术文档可以模拟组织和访问角色。

- 链路：资料同步→解析/版本→权限感知索引→检索/重排→引用回答→纠错反馈。
- 技术：06数据/RAG、02数据库/租户、05模型契约、11评测/trace、14部署；FastAPI、PostgreSQL/pgvector、BM25、模型适配层和一种观测工具即可起步。
- 对照：关键词、向量、混合+重排；按来源/问题家族分dev/test，分别测检索、回答有据、无答案、过期和越权。
- 深度：增量更新幂等、删除传播、索引版本切换、检索前权限过滤、故障降级/回滚。
- 证据：文档/标签版本、逐题结果、ACL测试、p50/p95、每成功任务成本、界面和runbook。

## P2 带业务操作的流程 Agent

**任务：** 处理服务工单或供应商请求：检索政策、读取状态、提出行动、必要时确认，再执行可审计操作。外部系统先用独立模拟服务，随后接授权测试环境。

- 链路：请求→任务状态/工具→建议/确认→外部提交→对账/通知→反馈。
- 技术：07harness、08LangGraph/耐久工作流、10MCP/授权、02幂等/队列、11–14评测与运行。
- 对照：规则流程、单Agent、规划/协作版本；固定模型、工具和预算，比较成功、人工接管、工具错误和成本。
- 深度：持久状态、审批绑定动作版本、幂等键、租约/并发、外部结果未知、撤销、重放与对账。
- 证据：状态迁移图、MCP工具、跨进程故障演练、重复投递、审计和用户可见恢复流程。

## P3 文档处理与人工复核

**任务：** 分类、抽取和核验公开或合成单据/申请材料，让低置信结果进入人工复核，修正回流到数据集。

- 链路：接入→解析/OCR/视觉模型→schema→领域规则→人工队列→导出/更新。
- 技术：05.6多模态、02异步/数据、11标签/评测、14交互/治理；12可选SFT或蒸馏。
- 对照：规则/传统解析、通用模型、领域适配；统计字段/文档/业务规则正确率，比较复核覆盖与错误/成本。
- 深度：格式/大小限制、取消、批处理幂等、字段溯源、复核冲突、脱敏和保留策略。
- 证据：标注规范、失败分层、复核界面、导出契约、版本、吞吐/延迟与人工工作量估算。

## P4 小模型服务与行为优化

**任务：** 为分类、结构化抽取或有界工具选择部署小模型，在业务质量约束下改进成本或延迟。

- 链路：数据/基线→本地模型→API→SFT/LoRA或蒸馏→负载评测→版本发布。
- 技术：03–04模型基础、12后训练、13推理、11实验、14交付；按硬件选llama.cpp/MLX LM或vLLM/SGLang。
- 对照：提示基线、适配前后、不同精度/上下文/并发；将训练收益和服务配置变化分开比较。
- 深度：泄漏检查、chat template/label mask、checkpoint/revision、显存/KV、warmup、排队和回滚。
- 证据：配置/日志、独立测试、硬件/模型版本、TTFT/TPOT/吞吐/内存、质量与每成功任务成本。

## 可选扩展

Multi-Agent从P2可分解任务开始，保留单Agent基线。Agentic RL需要可reset环境、可审计奖励和未见场景。GraphRAG、长期记忆、A2A及分布式推理按实际瓶颈选择，并测量增加机制带来的收益与代价。

## 所有项目共享的交付包

1. [任务卡](../../templates/task-card.md)：用户、流程、输入输出、错误成本、质量和预算。
2. 架构/契约：数据、控制、权限流，状态、重试与副作用责任。
3. 数据卡：来源/许可、标签规范、dev/test分组、隐私和版本。
4. [实验记录](../../templates/experiment.md)：强基线、逐题结果、公平对照、消融、失败分类与不确定性。
5. 运行包：干净安装、容器、部署、trace、负载/恢复、回滚与runbook。
6. 评审：他人复现、一次未见故障、一项需求变更和下一步技术判断。

报告真实测量并标明真实模型、模拟环境和合成数据范围。业务阈值由错误成本决定，严重越权或未授权操作单独处理。完成标准见[能力评审](assessment.md)。
