## 09.1 Decomposition and organization

`core` · Design under constraints and defend tradeoffs

Prerequisites: [07.3 Harnesses and agent/environment interfaces](../modules/07.md#unit-07-3), [11.2 Layered metrics and trajectory evaluation](../modules/11.md#unit-11-2)

### Knowledge outline

- Single agent, fixed parallelism and multi-agent choices
- Supervisors, hierarchies, peers/swarms and blackboards
- Specialties, tool scope, context and responsibility
- Independence, dependencies, constraints and termination
- Coordination overhead, failure propagation and hypotheses

### Reading and scope

[Stanford CS329Z: Engineering AI Agents](https://cs329z.stanford.edu/) — Agent-engineering spine connecting frameworks, data, optimization, evaluation and safety through released material.

Multi-agent topic with papers and framework examples.

### Practical evidence

Propose a testable collaboration hypothesis for research/analysis.

### Self-check

1. When does a multi-agent system beat a single agent? What extra costs does it bring (coordination, tokens, error propagation)?
2. A multi-agent system is slower and more expensive than the single-agent baseline, with no quality gain. How do you analyze why?
3. Design an organization (supervisor, hierarchy or peers) for “write an industry research report”, with each agent’s role, tool scope and termination conditions.

## 09.2 Communication, handoffs and ledgers

`advanced` · Implement a small system and verify behavior

Prerequisites: [09.1 Decomposition and organization](../modules/09.md#unit-09-1), [01.3 Async, concurrency and cancellation](../modules/01.md#unit-01-3)

### Knowledge outline

- Message schemas, task/results and routing
- Handoffs, subagents as tools and message boards
- IDs, ownership, leases, state and artifact ledgers
- Loss, duplicates, ordering, timeout and deadlock
- Communication tokens, compression and contamination

### Reading and scope

[Google Agent Development Kit](https://google.github.io/adk-docs/) — Second framework option: sessions, tools, workflow agents, deployment and evaluation.

Multi-agent, handoff, sessions and communication examples.

### Practical evidence

Coordinate two workers producing artifacts.

### Self-check

1. Compare handoffs (transferring control) with subagents called as tools, in how context passes and where responsibility lies.
2. Two agents deadlock waiting on each other, or two agents run the same task. How do you fix this with a task ledger and leases?
3. Design an inter-agent message schema (task ID, ownership, status, artifact references, timeout) and explain how you would compress what gets communicated.

## 09.3 Isolation and shared state

`advanced` · Diagnose failures, compare and repair

Prerequisites: [09.2 Communication, handoffs and ledgers](../modules/09.md#unit-09-2), [02.3 Transactions, idempotency and consistency](../modules/02.md#unit-02-3), [10.4 Untrusted data and tool safety](../modules/10.md#unit-10-4)

### Knowledge outline

- Task contexts versus shared facts
- Transactions, revisions and concurrent merging
- Directories, worktrees and artifact ownership
- Identity, permissions, credentials and leakage
- Recovery, cancellation and cleanup

### Reading and scope

[Deep Agents](https://docs.langchain.com/oss/python/deepagents/overview) — Study filesystem offloading, subtask isolation, planning and harness lifecycle.

Subagents, filesystem/backends and isolation.

### Practical evidence

Inject a concurrent write conflict and verify isolation/merging.

### Self-check

1. Why give parallel agents that edit code separate workspaces or git worktrees? How do you separate shared facts from task-private context?
2. Two parallel agents update shared state at once and one overwrites the other. How do you handle it with revision numbers or a merge strategy?
3. When assigning identities and credentials to agents, how do you stop one agent from gaining another’s permissions or leaking data?

## 09.4 A2A and cross-service collaboration

`advanced` · Explain mechanisms, limits and choices

Prerequisites: [09.2 Communication, handoffs and ledgers](../modules/09.md#unit-09-2), [10.3 SDK development, auth and remote deployment](../modules/10.md#unit-10-3)

### Knowledge outline

- Discovery, agent cards and contracts
- Messages, task lifecycle, progress and artifacts
- Sync/async, streaming, reconnect and cancellation
- Cross-service identity, access and trust
- A2A agent collaboration and MCP tool integration

### Reading and scope

[A2A Protocol](https://a2a-protocol.org/latest/) — Agent cards, tasks, messages and cross-service collaboration.

Protocol overview, agent cards, tasks, messages and artifacts.

### Practical evidence

Diagram cross-organization agent data and authorization flows.

### Self-check

1. Explain agent cards, the task lifecycle and artifacts in A2A. How does A2A’s role differ from MCP’s?
2. A remote agent called across services stops responding for a long time. How does your system handle streamed progress, reconnection and cancellation?
3. Agents from two companies collaborate over A2A. How should authentication, authorization and trust boundaries be designed?

## 09.5 Collaboration evaluation and failure diagnosis

`advanced` · Diagnose failures, compare and repair

Prerequisites: [09.3 Isolation and shared state](../modules/09.md#unit-09-3), [11.4 Experiments, A/B tests and uncertainty](../modules/11.md#unit-11-4)

### Knowledge outline

- Equal model/data/tools/token/time budgets
- Task/subtask quality and coordination cost
- Redundancy, drift, false consensus and loops
- Single/workflow/collaboration baselines and ablations
- Long-task stability, reproducible traces and negative results

### Reading and scope

[Inspect AI](https://inspect.aisi.org.uk/) — Open evaluation framework; study datasets, solvers, scorers and sandboxes.

Evaluation framework and multi-step/tool scoring.

### Practical evidence

Show which tasks justify a collaboration design.

### Self-check

1. When comparing multi-agent and single-agent systems, why must the model, tools, tokens and time budget be held equal?
2. A multi-agent system shows false consensus or task drift. How do you spot and attribute it from traces?
3. Design ablations that show which part of a multi-agent setup (division of labor, parallelism, peer review) actually produces the gain.
