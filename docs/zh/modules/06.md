## 06.1 文档入库与数据质量

`core` · 诊断：定位失败、设计对照并修正

先修：[02.2 SQL、数据建模与索引](../modules/02.md#unit-02-2)

### 知识框架

- 数据源连接、增量同步、来源许可与数据卡
- PDF/HTML/Office/OCR、布局、表格和编码
- 清洗、去重、内容 hash、文档/段落 ID 与版本
- 按标题/语义/结构切分、overlap 与 metadata
- 批处理、失败重跑、幂等索引和删除传播
- 解析工具选型（Docling、MinerU、PaddleOCR、Unstructured）或云端文档智能服务（Azure Document Intelligence、AWS Textract），按文档类型评估解析质量
- 企业数据平台：Spark/Databricks 批处理、Airflow 编排、Lakehouse 表格式（Delta/Iceberg）与数据血缘

### 资源与阅读范围

[Docling Documentation](https://docling-project.github.io/docling/) — 开源文档解析工具：PDF/Office/HTML、版面、表格、OCR 与结构化切块；用来理解解析质量如何影响检索。

支持格式、PDF 版面/表格/OCR 管线与 chunking；对照 MinerU 的中文文档解析效果。

### 动手任务

为一个有修订和删除的数据源建立可重放入库流水线。

### 自测题

1. 比较固定长度切块、按文档结构切块和语义切块；overlap 和元数据分别起什么作用？
2. 用户反馈回答引用了一份已删除的旧版文档，你如何设计文档 ID、版本和增量同步，确保删除真正生效？
3. 面对扫描 PDF、带复杂表格的财报和网页三类文档，你会如何选择解析工具并评估解析质量？

### 知识框架

- bi-encoder、query/document 表示与训练目标
- cosine/dot/L2、归一化、维度和分布

- 按 MTEB/C-MTEB 与自有数据选 embedding 模型（BGE、Qwen3-Embedding 等）；Matryoshka 维度与量化
- 用 hard negatives 微调 embedding/reranker 及其评测

### 资源与阅读范围

[Sentence Transformers: Retrieve and Rerank](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html) — 明确 bi-encoder 召回与 cross-encoder 重排的质量/速度取舍。

### 动手任务

### 自测题

1. 解释双塔（bi-encoder）embedding 的训练目标，以及为什么“语义相似”不等于“与问题相关”。
2. 换用新的 embedding 模型后，部分领域的检索效果变差了。你如何评估、迁移并重建索引而不影响线上？
3. 如何选择 embedding 模型：MTEB/C-MTEB 分数、自有数据评测、维度和成本？什么时候值得用难负例微调？

- 拒答、澄清、过期/冲突知识与用户可解释性

### 资源与阅读范围

[ALCE: Enabling LLMs to Generate Text with Citations](https://arxiv.org/abs/2305.14627) — 引用生成的基准论文；定义引用召回/精确率，区分回答正确、证据支持与引用正确。

### 自测题

1. 解释“答案正确”“有依据（faithful）”和“引用正确”是三件不同的事，并各举一个只满足其中一项的例子。
2. 检索到的两份文档互相矛盾（新旧两版政策），模型却只引用了旧的，你如何在上下文组装和提示中处理？
3. 设计拒答机制：什么时候应回答“资料中没有相关信息”？如何衡量拒答率和误拒率？

## 06.9 视觉文档检索与长上下文取舍

`advanced` · 设计：在约束下选择架构并论证取舍

先修：[06.4 混合召回与重排](../modules/06.md#unit-06-4), [05.6 视觉、文档与多模态输入](../modules/05.md#unit-05-6)

### 知识框架

- 页面图像直接检索：ColPali/多向量 late interaction 与 OCR 管线对照
- 表格、图表、扫描件与版面信息的检索与回答
- 长上下文窗口与 RAG：成本、延迟、position bias 和 context rot
- 混合策略：检索后整文阅读、长文档 prompt caching 与分层摘要
- 多向量索引的存储/延迟成本与评测方法

### 资源与阅读范围

[ColPali: Efficient Document Retrieval with Vision Language Models](https://arxiv.org/abs/2407.01449) — 直接对页面图像做多向量检索的论文与 ViDoRe 基准；对照 OCR+ 文本管线。

论文方法与 ViDoRe 评测部分；长上下文取舍结合 05.4 与 05.10。

### 动手任务

在含表格/图表的 PDF 集合上比较 OCR+ 文本检索、页面图像检索与长上下文直读三种方案的质量、延迟和成本。

### 自测题

1. 解释 ColPali 直接检索页面图像的原理（多向量 late interaction），以及它与 OCR 流水线相比的优劣。
2. 模型支持百万 token 上下文后还需要 RAG 吗？从成本、延迟、位置偏差和权限四个方面论证。
3. 设计一个混合策略：先检索定位文档，再整篇阅读或使用缓存的长文档；如何评估它与纯 RAG 的差异？
