# Entry diagnostic: choose a starting point

Use runnable code, small calculations and explanation to identify existing skills. Consult official resources or demonstrate prior work. Begin corresponding modules for unfamiliar topics.

| Diagnostic | Demonstration | Modules |
|---|---|---|
| D0 Programming | File I/O, errors, functions/modules, tests and debugging |01.1–01.2/01.4–01.6|
| D1 Services | JSON validation, dependency deadlines/cancellation, errors, async versus parallelism |01.3,02.1,05.1|
| D2 Data | SQL/indexes, concurrent updates, transactions/constraints/version checks |02.2–02.4|
| D3 Engineering | Clean setup, dependencies/config, Git, Linux process/network diagnosis |01.5–01.6,02.6|
| D4 Math/ML | Cosine, softmax/cross-entropy, training/test and overfitting |03|
| D5 Models | Token→embedding→attention→logits, shapes, training/inference |04|
| D6 Evaluation | Labels, denominators, dev/test, paired comparison on ten examples |11.1–11.4|

With D0–D3, start an API product slice early. Strengthen D4–D5 in parallel and complete D6 before retrieval optimization. Record demonstrated evidence, waived units and remaining gaps. See the [knowledge tree](knowledge-tree.md).
