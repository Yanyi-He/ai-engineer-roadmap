## 08.1 LangGraph state graphs

`core` · Implement a small system and verify behavior

Prerequisites: [07.2 Reasoning/action loops and planning](../modules/07.md#unit-07-2), [01.2 Types, schemas and configuration](../modules/01.md#unit-01-2)

### Knowledge outline

- StateGraph, schemas, nodes and edges
- Typed state, reducers and accumulated messages
- Conditional routing, loops, termination and debugging
- Model/retrieval/tool nodes and dependencies
- Fixed workflows and dynamic graphs
- LangChain/LangGraph 1.0: create_agent on LangGraph and middleware (PII redaction, summarization, human approval); create_react_agent is deprecated

### Reading and scope

[LangChain Academy: Introduction to LangGraph](https://academy.langchain.com/courses/intro-to-langgraph) — Official complete 55-lesson, roughly six-hour course on state, interrupts, memory and deployment.

State, nodes, edges, reducers and graph execution.

### Practical evidence

Implement a task as fixed and dynamically routed graphs.

### Self-check

1. Explain the roles of State, nodes, edges and reducers in LangGraph. Why does a message list need a reducer such as add_messages?
2. A graph with conditional edges loops forever. How do you debug it and set termination conditions (for example recursion_limit)?
3. Use LangGraph to implement “retrieve → generate → self-check → rewrite the query on failure”, and draw the nodes and conditional edges.

## 08.8 Low-code agent platforms and platform-versus-code decisions

`advanced` · Design under constraints and defend tradeoffs

Prerequisites: [07.1 Choosing workflows and agents](../modules/07.md#unit-07-1), [05.3 Structured output and tool execution](../modules/05.md#unit-05-3)

### Knowledge outline

- Dify/Coze/n8n workflow canvases, knowledge bases, plugins/tools and app publishing
- Platform versus code: iteration speed, control, testing, versioning and cost
- Extension paths: custom tools, HTTP nodes, MCP integration and plugin development
- Self-hosting, licenses, multi-tenancy and data boundaries
- DSL export, version control, and how to fill evaluation/observability gaps
- Triggers and steps for migrating a platform prototype to a code service
- Enterprise low-code counterparts: Copilot Studio and Power Automate in North America, Dify and Coze in China; licences (Dify's multi-tenant and logo terms), single-instance throughput limits and when to move to code

### Reading and scope

[Dify Documentation](https://docs.dify.ai/en/home) — Maintainer docs for an open low-code LLM app platform: workflows, knowledge bases, tools/plugins and self-hosting; note its custom license.

Workflow, knowledge-base, tools/plugins and self-hosting sections; compare equivalent features in Coze and n8n.

### Practical evidence

Build a business assistant with a knowledge base and tool calls in Dify, reimplement the flow in code and compare build time, testability and failure handling.

### Self-check

1. What does each of Dify, Coze and n8n suit? What do low-code platforms trade in iteration speed versus control compared with code?
2. A prototype the business team built in Dify is unstable and has no regression tests. How would you add evaluation and observability, or decide to migrate to code?
3. List the triggers and steps for migrating a platform prototype to a code service: DSL export, test sets, permissions, self-hosting and licensing.
