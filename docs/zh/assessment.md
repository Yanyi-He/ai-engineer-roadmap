# 能力评审：能不能独立做应用 AIE 的工作

[自测题](self-check.md)检查单个单元，这一页评审一个完整作品。这套标准是本路线自己定的，用来判断作品够不够拿去求职。最好请没参与开发的人来评：从干净环境把作品跑起来，再临时提一个改动。只有自己评的，就如实记成自评。

| 能力 | 至少达到的独立表现 | 证据 |
|---|---|---|
| 定义问题 | 把业务痛点转成任务、非目标、错误成本与验收条件；解释为何需要 LLM | 任务说明、基线、用户反馈或明确代理标签 |
| 构建系统 | 独立实现数据→模型/检索→工具→结果；解释 schema、状态、事务和权限 | 可运行仓库、架构图、契约及关键代码 |
| 设计实验 | 固定 dev/test、标签和版本；分层诊断；做一项公平消融并承认负结果 | 原始逐题结果、数据卡、错误分析 |
| 运营与恢复 | 在限流、重复投递、崩溃和授权失效下表现有边界；演练回滚 | 运行手册、故障注入、脱敏 trace、回滚记录 |
| 模型基本功 | 本地跑一个模型，解释量化、token、上下文和性能测量条件 | 权重 revision、硬件、质量/延迟/内存结果 |
| 沟通与判断 | 面对新需求能修改设计；指出何时不用 agent、何时不该上线 | 设计答辩、决策记录、下一步假设 |

每项按 0–3 打分：0 跑不起来或讲不清；1 能照着教程复现；2 能独立修改和排查；3 能应对没见过的约束并讲清取舍。**六项都达到 2，并且下面的底线都守住，才算通过。**

底线：不编造实验结果；在公开测试集上反复调参得到的结果不能叫盲测；不跨用户泄漏数据；会执行操作的系统，没有授权就不能产生实际效果；失败要让用户看得到；照着文档能复现。医疗、金融等高风险领域还需要该领域的专业评审。

评审流程建议：20 分钟讲任务和架构；30 分钟现场排查一个预先藏好的故障；30 分钟做一个小改动；20 分钟讨论实验设计和取舍。可以预留三类隐藏题：过期文档、审批之后动作被改了、外部提交之后进程崩溃。按现场独立完成的情况打分。

通过说明你有一个拿得出手的应用 AIE 作品，以及一组能独立完成的能力。长期维护生产系统、跨团队协作和算法研究，这套评审测不出来。申请后训练或推理平台岗位，还要完成对应专项的实验。

按作品涉及的内容，抽查 [L13 无框架 Agent、L14 评测环境与评分器、L15 数据策展](labs.md)；训练和自托管模型按目标方向评审。中期和最终复核最好由开发者以外的人记录。

评测怎么接进作品，见[评测实操指南](evaluation-playbook.md)和实验 L16、L17。
