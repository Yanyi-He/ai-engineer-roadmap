# 17 个实验

这些实验最好都围绕同一个作品来做，一步步扩展。L02、L03、L04 附有可离线运行的参考实现（检索指标、外部提交之后的恢复、带有效时间的记忆）；接真实模型、MCP 和部署的部分留给你自己完成。[参考实现的运行说明](../../labs/README.md)

每做一个实验，都记下任务、数据版本、配置、运行命令、每道题的结果、失败分析和下一步要改什么。实验顺序见[学习路径](learning-path.md)；L09 模型基础可以和前面的 API 实验同时做，L11、L12 按目标方向选做。

## L01

**有边界的模型接口。** 先修01.1–01.3、02.1、05.1–05.3。为一个工单分类任务定义输入、输出和错误契约；先用可注入的假模型跑通，再接一个实际 provider 或本地模型。允许输出为“信息不足”。

交付：HTTP API、严格输出 schema、请求 deadline、单次有限修复、取消传播、token/费用账本。故障夹具至少包含无效 JSON、schema 正确但业务值非法、流中断、429、依赖超时、超长输入。重试共用总 deadline 和预算，不能重新起算。分类错误与接口错误分别统计。

验收：独立运行这些故障，证明任务不会无限重试或无限排队；记录输入输出脱敏规则。固定真实任务集比较自由文本与结构化输出的“格式有效率”和“任务正确率”，两者分开报告。口试：HTTP 成功、schema 成功、业务成功分别表示什么？

## L02

**先测检索，再做 RAG。** 先修06.1–06.4、11.1–11.2。参考实现：`python3 -m labs.retrieval --split dev --k 3`。它实现 BM25、Recall@k 和分级 nDCG；数据是一小份英文合成样例，不含向量模型和生成部分。

扩展：用可再分发资料建立文档级 ID、版本、权限和证据标签。按来源/问题家族划分 dev 与 holdout，同一文档改写不要跨组。比较 BM25 → dense → hybrid → reranker；固定候选预算、输入和同一组查询。分别记录召回、排序、回答有据率、无答案拒答和泄漏。没有相关文档的问题，Recall 记为未定义并单独统计，不要算成 100%。

验收：交付逐题排名及 qrels、索引和嵌入版本；解释至少三个失败来自 ingestion、retrieval、rerank 还是 generation。人为放入过期事实和无权文档，验证在检索前限制范围。小样本报告分子/分母；需要区间时按独立问题家族成组重采样。公开 holdout 只能用于教学复现；正式项目另留未调参的私有测试集。

## L03

**跨崩溃的执行与人工审批。** 先修02.3–02.4、07.4、08.1–08.3。参考实现 `labs.durable` 把流程库和外部服务模拟器放在两个 SQLite 数据库，模拟“外部效果已提交，流程尚未记账”的真实间隙。

扩展：使用 LangGraph 持久化或明确状态机实现检索→生成建议→等待审批→执行；审批在服务端绑定用户、run、动作摘要和版本。对审批前、外部提交后、checkpoint 后分别杀进程；用同一 run 恢复。再启动两个 worker 争抢同一 stage。记录 lease、fencing token、唯一动作键、outbox 和超时的用途。

验收：审批前无效果；允许重复投递；支持幂等键的外部端点只产生一次效果。再替换成不支持幂等的端点，展示为何 checkpoint 无法消除“提交结果未知”；设计对账或人工处理。不要笼统地说做到了 exactly-once。日志中能解释每次状态迁移，恢复后旧审批不能授权已修改的动作。

## L04

**会被纠正、过期和撤回的记忆。** 先修07.5–07.6、02.2–02.3。参考实现 `labs.memory` 演示 owner/scope 隔离、有效时间、版本 CAS、幂等写入和逻辑遗忘。Principal 由调用端注入，参考实现本身不做身份认证。

扩展：把“偏好 A→纠正为 B→计划将来变为 C→撤回”写成事件序列，并在不同时间点提问。区分事实生效时间和系统知道这条事实的时间；若要回答“当时系统知道什么”，补充 transaction-time 版本，单一 valid-time 不够。自动收集低风险情节记忆，高影响偏好进入冲突处理；不要要求用户逐条审批所有记忆。

验收：比较无记忆、等 token 历史、普通向量检索和更新感知检索；固定模型和上下文预算，分开测写入错误、过期召回和推理错误。两个客户端并发纠正同一事实不能静默覆盖。撤回要覆盖历史查询、向量索引、缓存和导出；参考代码仅保证其 SQLite 值及来源被清空，不代表磁盘取证或备份删除。接 MCP 后，再测伪造 owner 和越权查询。

## L05

**可授权的 MCP 工具与受限执行。** 先修10.1–10.4、02.5；沙箱深入10.5。自行实现两个只读工具与一个受审批写工具。基于官方 SDK 做 stdio 本地客户端；远程 HTTP 版本另加真实身份验证与授权，不能把工具参数里的 user_id 当身份。

交付：工具 schema、调用方身份→数据范围映射、分页、错误分类、速率和输出大小限制、版本兼容说明。测试错误 audience、过期凭证、缺失 scope、未知字段、恶意文档指令、授权撤销和客户端断线。凭证不进入模型上下文。若加入代码执行，使用独立 worker；限制出网、挂载、CPU、内存、进程和时间，设计销毁及日志回收。

验收：未经授权的读写在服务端被拒；恶意文档不能获得更高工具权限；危险动作只凭正确版本的审批执行。容器启动成功不能证明沙盒安全。MCP 是工具交互协议，不能替代检索、执行状态机或业务授权。学习目标是能论证信任边界，不要求复刻微虚拟机平台。

## L06

**评测、观测和发布构成同一条反馈链。** 先修11.1–11.6、14.2–14.6。选一个前面已经完成的系统，打通请求→模型→检索→工具→结果的 trace；版本化 prompt、模型、工具、索引和数据集。不得把生产私密输入直接传到公共 tracing 服务。

交付：人工校准的小评测集；包含错误类目的 grader；按问题配对比较的回归报告；脱敏 trace；一次部署、迁移和回滚操作记录。阈值按业务损失声明，不能只放“成功率>90%”。观察模型限流、索引不可用、worker 被杀和队列过载时的表现，记录 p50/p95、错误率、花费和队列深度。

验收：盲查一条失败轨迹，定位是数据、检索、模型、工具还是 runtime；证明断网/限流不会产生无限重试；在演练环境回滚一版有问题的 prompt 或 schema。LLM judge 先对照人工标签测一致性和误判，区分置信区间、run 间变化与业务上重要的差异。多智能体只在可分解任务上与单 agent 同预算比较，不用角色数量当效果。

## L07

**本地模型与推理性能的基本功。** 先修13.1–13.5；GPU与分布式深入13.6。Mac 优先 MLX-LM/llama.cpp；NVIDIA 条件下选择 vLLM 或 SGLang。先完成[资源预算表](../../templates/resource-budget.md)，检查真实内存、模型许可证和 chat template，再选装得下的小模型，不指定“最新模型”作为固定前提。

交付：硬件、权重 revision、依赖锁定、量化设置、prompt/output 长度、batch/concurrency、重复次数、预热和缓存条件。用同一任务集比较原精度/量化；记录正确率、TTFT、每 token 延迟、端到端延迟和峰值内存。流式测试说明 TTFT 是何处测量，冷启动与热服务分开。

验收：解释权重内存约等于参数量×位数/8，但运行还需要 KV cache、激活和后端开销。分别估算权重、KV、激活和运行时开销，解释带宽/计算上界；用 profiler 或服务器指标定位一项实际瓶颈；性能比较固定输出长度或同时报告长度变化。量化后更快但质量下降时，画质量/延迟取舍。没有 GPU 可先完成 CPU/Metal 实验；不得据此声称精通 CUDA、分布式训练或线上 GPU 集群。

## L08

**SFT/LoRA：完成一次可归因的行为适配。** 先修03.4–03.5、04.1/04.5、12.1–12.4。选分类、字段抽取或有界工具选择任务，先建立未适配模型和提示基线。

按实体、模板或时间分组数据；标明授权、去重和dev/test。核对chat template、special tokens、padding、label mask与shift；用小批量检查loss和梯度，再做资源预算内的LoRA实验。保存模型revision、adapter、配置、seed、数据hash、学习曲线、checkpoint和训练资源。

验收：重载adapter复现结果，对同一未见任务集比较提示/SFT表现，报告结构正确、任务正确、其他能力退化、训练时间和推理成本。检查泄漏、过拟合、OOM与恢复。负结果保留原始记录和原因。理解量化训练的计算/存储精度及推理量化的区别。

## L09

**PyTorch与Transformer最小实现。** 对应03.1–03.5、04.1–04.2/04.6。实现张量输入→embedding→causal attention→FFN/残差→logits→loss；在小规模数据上完成forward/backward/optimizer与生成。

验收：标出每层shape，手算一个attention或交叉熵例子，检查因果mask、padding和label shift；用小数据过拟合验证训练链路。解释train/eval、采样、KV cache、seed及浮点精度；保存可重跑的小实验。

## L10

**单Agent与Multi-Agent同预算比较。** 对应09.1–09.3/09.5、11.2–11.4。从可分解的调查或工单任务开始，保留workflow和单Agent基线，再实现manager/worker或planner/executor一种结构。

验收：固定工具、模型、上下文和总token/时间预算，测成功、成本、延迟、通信和失败传播；引入worker失败、重复消息、共享状态冲突与取消。记录子任务ID、来源、结构化结果和父子trace。说明收益来自并行、专门工具或额外推理，并给出采用建议。

## L11

**多模态文档或语音交互。** 对应05.6–05.7、14.3。选择公开文档字段提取，或语音请求→工具执行→响应的最小产品。

验收：文档分字段标注并保留页码/bbox/来源，比较规则/OCR/视觉方案及人工复核；语音分开测识别、工具正确和端到端延迟，处理打断、取消与超时。保留失败分层、隐私与保留策略、产品演示和成本。

## L12

**偏好、RL或蒸馏专项。** 对应12.5–12.9，选一个方向深入，并先完成L08的训练/评测基础。

- DPO/偏好：检查偏好来源、一致性、reference配置、长度偏差；对照SFT和独立人工评价。
- Agentic RL：先做可reset环境、终止条件、可审计reward；记录轨迹、rollout吞吐和预算；比较workflow/prompt、SFT、RL，测未见组合与reward hacking。
- 蒸馏：明确teacher/student与许可，记录生成/过滤成本和错误迁移，比较仅提示、SFT与蒸馏收益。
- Bandit/OPE：真正按行为分布采样并记propensity；模拟中核对IPS/SNIPS/DR，报告overlap、ESS和裁剪敏感性，按用户/会话重采样。

验收：先用已知正负例检查reward/parser，再冻结数据、模型与推理预算，交付可复现结果和归因。记录采样策略版本、on/off-policy更新、归一化与loss reduction；分别验证数学任务和工具环境。先小规模估算token、显存和时间，再决定扩展；在结果中明确完成的是偏好学习、bandit、蒸馏或多步RL。

## L13

**先实现无框架Agent内核，再迁移抽象。** 先修05.1–05.4、07.1–07.3。使用一个模型适配器和明确的Action/Observation契约，实现循环、工具注册/解析、执行、结果回传、停止、上下文预算和事件日志。工具先使用独立的只读模拟服务。可以使用provider原生tool calling或教学JSON协议，说明参数校验、授权和执行分别由谁负责。

先以scripted model验证坏格式、未知工具、工具异常、观察截断、预算耗尽、取消和重复回复；再在小型真实任务集运行。保存输入、工具动作、可观测结果、终止原因与花费。补一个小型倒排/BM25实现或解释现有参考实现的时间复杂度，再接入检索工具。

验收：能修改工具协议、终止或压缩策略并解释影响。将同一任务迁移到LangGraph或DSPy，比较抽象节省的代码、状态/重试责任和结果差异。保持模型、数据和预算一致。参考CS329Z HW1的能力顺序，使用自己的任务和实现。

## L14

**建立可验证的环境任务。** 先修11.1–11.4、11.8、10.4、02.6。用[任务模板](../../templates/benchmark-task.md)定义request、environment、stopping和scorer，固定模型、Agent、依赖与初始状态。

先用oracle/已知正确解跑通完整评分；再加入空操作、错误/不完整结果、不同实现的正确解和投机解。评估verifier误奖/漏奖，区分环境搭建失败、模型/Agent失败与评分器错误。文件存在或Agent自述成功分别与真实内容/状态核验。

验收：从干净环境重建，保留所有独立试次、artifact、verifier日志与失败分类；报告n、k、成本、延迟与评分规则。区分pass@k的候选成功和pass^k的重复可靠性，说明相关试次与缓存条件。把一条失败追溯到Agent、环境或评分器，并验证修复。

## L15

**从失败到数据策展。** 先修06.1、11.1、12.1、12.10。选一个业务失败类型，建立目标分布与数据清单，使用[数据卡](../../templates/dataset-card.md)记录来源、权限、标签、版本和处理链。

构造包含精确重复、近重复、来源差异、少数类与污染样本的小型集合。先建立来源/实体/会话/时间及近重复群组，再分组切分，避免相似样本跨集；处理规则仅用训练/开发数据选择，独立测试保持冻结；记录删除率、各切片覆盖与潜在误删。用少量合成回答/轨迹建立验证过滤与成本账本，单独审查教师错误。

验收：比较原数据、筛选/去重和加入合成数据的方案，固定任务/模型/预算，保留每条数据血缘和一个独立测试集。可以在prompt示例、检索或小模型训练中选一个用途。解释新增数据解决了什么失败，以及何时需要更多人工标注。

## L16

**用Ragas测RAG各层。** 先修11.10–11.11、06.6。按[操作指南](evaluation-playbook.md)运行固定版本的真实ID指标，说明qrels/ID、排序指标与LLM context指标的区别。接入自己的RAG，保留实际检索内容和未修正输出；reference只交给评分器。

验收：逐题/切片报告检索、faithfulness、事实正确、拒答和引用；列明judge/embedding依赖、n/分母、未测/错误与版本。用人工标签找到一个grader误判，说明缺失证据、资料过期和生成错误怎样区分。参考夹具无模型API调用；语义judge按需配置并记录费用。

## L17

**把评测接成回归和发布检查。** 先修11.6、11.10、11.12。运行[参考目录](../../labs/evaluation/README.md)与pytest/promptfoo正常和破坏版本，核对退出码，再接一项真实prompt/模型/检索/工具改动。

验收：固定baseline、数据与评分配置，交付逐题配对、关键切片、平均变化、统计假设、覆盖分母和错误。绝对质量底线、相对退化和安全项分别判断；NaN/评分超时和漏case有明确失败状态。保留JSON/CI artifact、人工复核、baseline晋升与回滚记录。参数阈值按业务损失和波动制定。
