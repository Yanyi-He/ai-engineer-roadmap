## 13.1 本地小模型部署

`core` · 实现：独立完成小型实现并验证行为

先修：[02.1 HTTP、API 与流式交互](../modules/02.md#unit-02-1), [04.1 Tokenizer、语料与训练目标](../modules/04.md#unit-04-1)

### 知识框架

- 硬件/内存、模型大小、许可证和权重 revision
- Mac MLX-LM/llama.cpp 与 Linux/GPU 路径
- GGUF、safetensors、tokenizer 与 chat template
- 本地 HTTP 服务、流式、并发和真实任务评测
- 权重下载、缓存、离线运行与资源记录

### 资源与阅读范围

[MLX LM](https://github.com/ml-explore/mlx-lm) — Apple silicon 的推理与 LoRA 实验入口，内存仍需实测。

安装、模型加载、生成、量化与 LoRA 示例。

### 动手任务

部署装得下的小模型，并保存质量/延迟/内存记录。

### 自测题

1. 比较 GGUF 与 safetensors 格式，以及 MLX、llama.cpp 和 vLLM 分别适合什么硬件和场景。
2. 本地模型输出格式混乱或不停止，你会检查哪些地方（chat template、停止词、量化版本）？
3. 给定一台 16GB 内存的 Mac，选一个能运行的模型和量化等级，并用真实任务评测它的质量和速度。

## 13.2 Prefill、Decode 与 KV Cache

`core` · 诊断：定位失败、设计对照并修正

先修：[04.2 Transformer 完整计算链](../modules/04.md#unit-04-2), [13.1 本地小模型部署](../modules/13.md#unit-13-1)

### 知识框架

- 自回归生成、prefill 与 decode 的数据流
- compute-bound/memory-bound 与带宽
- KV 大小、上下文、batch 和并发
- PagedAttention、prefix cache 和 cache eviction
- 长上下文、缓存命中和服务公平性

### 资源与阅读范围

[vLLM Documentation](https://docs.vllm.ai/en/latest/) — 研究 continuous batching、KV cache、serving 和压测；Linux GPU 路线。

Serving、architecture、KV cache 和性能相关文档。

### 动手任务

估算并实测上下文与并发变化对 KV 内存的影响。

### 自测题

1. 解释 prefill 和 decode 阶段的计算特点；为什么 prefill 偏计算受限，decode 偏内存带宽受限？
2. 计算一个 32 层、8 个 KV 头、head_dim=128、FP16 的模型在 8K 上下文下，每个请求的 KV cache 有多大。
3. 解释 PagedAttention 和前缀缓存如何提高显存利用率，以及长上下文请求如何影响其他请求的公平性。

## 13.3 批处理、调度与服务框架

`advanced` · 实现：独立完成小型实现并验证行为

先修：[13.2 Prefill、Decode 与 KV Cache](../modules/13.md#unit-13-2), [02.4 缓存、队列与后台任务](../modules/02.md#unit-02-4)

### 知识框架

- static/dynamic/continuous batching
- vLLM/SGLang 的服务入口、模型适配和配置
- 请求队列、admission、prefill/decode 调度
- streaming、取消、超时和故障隔离
- prefix cache、speculative decoding 和收益条件
- speculative sampling 的 draft/verify/accept 校正条件；区分有损近似和分布保持加速
- chunked prefill 与 prefill/decode 分离（DistServe、Mooncake）；KV cache 卸载与跨请求共享

### 资源与阅读范围

[vLLM Documentation](https://docs.vllm.ai/en/latest/) — 研究 continuous batching、KV cache、serving 和压测；Linux GPU 路线。

OpenAI-compatible server、batching、调度与指标。

### 动手任务

固定 workload 比较并发、吞吐和尾延迟。

### 自测题

1. 解释静态批处理、动态批处理和连续批处理（continuous batching）的区别；为什么连续批处理能大幅提高吞吐？
2. 解释投机解码的 draft/verify/accept 流程；为什么它能保持输出分布不变？什么情况下加速效果差？
3. 解释 chunked prefill 和 PD 分离（如 DistServe、Mooncake）要解决的问题，以及它们的部署代价。

## 13.7 资源核算、Roofline 与优化判断

`core` · 诊断：定位失败、设计对照并修正

先修：[03.1 线性代数与数值基础](../modules/03.md#unit-03-1), [04.2 Transformer 完整计算链](../modules/04.md#unit-04-2)

### 知识框架

- 参数、精度、梯度、优化器、激活、KV 与运行时开销分账
- prefill/decode、训练 forward/backward 与 batch/序列长度的计算量
- FLOP/s、带宽、算术强度、roofline 与 compute/memory-bound
- 内存上界、实际可用容量、缓存/碎片和并发预算
- 理论估算→profiler/服务指标→误差解释→一次针对性优化
- 训练 scaling law、推理计算和业务收益的关系与外推限制

### 资源与阅读范围

[CS336 Lecture 2: PyTorch and resource accounting](https://github.com/stanford-cs336/lectures/blob/main/lecture_02.py) — 代码讲义可读，可核算内存、FLOPs 和算术强度。

Lecture2 的内存/FLOPs/arithmetic intensity，配合 Lecture10 的推理负载；先做估算再测量。

### 动手任务

为一个模型配置建立内存和计算预算表，做小规模测量，解释估算误差并判断下一步优化位置。

### 自测题

1. 解释 roofline 模型和算术强度；如何判断一个算子是计算受限还是内存受限？
2. 你估算的推理吞吐是实测值的 3 倍，列出可能解释差距的因素，并说明如何用 profiler 验证。
3. 分别估算 7B 模型训练时每个 token 和推理时每生成一个 token 的 FLOPs（约 6N 和 2N），并说明这些估算在什么情况下失效。
